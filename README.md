# 电气控制系统仿真软件（Unity 离线复刻）

本项目是在 Unity 2022.3.62f3c1 中对“电气控制系统仿真软件”核心实训功能的离线复刻。视觉、模型、端子位置和交互以原始 Windows 程序的实际运行画面为基准，说明书与配置文件只用于补充理解。

程序跳过登录，启动后直接进入电气实训室。默认离线运行；可手动连接西门子 S7-1200、S7-1500 进行 PLC 联动。账号、在线更新、云端考试、Modbus 和原竞赛平台接口不属于当前范围。

首次下载请先阅读[下载与恢复](#下载与恢复)，确认模型、贴图和字体已经下载完整，再打开 Unity。详细故障处理见[项目恢复说明](Docs/project-recovery.md)。

## 当前能力

- 使用 Built-in Render Pipeline，启动场景为 `Assets/Scenes/ElectricalTraining.unity`。
- 使用原 `Experiment` 实训室、电控柜、设备、端子排、材质、贴图和 UI 资源。
- 支持视角、拖动、接线、仿真、排故五种互斥模式。
- 支持接线视角（柜体全景）和排故视角（柜体正面近景）。
- 支持电线、跳线、端子吸附、固定柜面折点、导线选中高亮、节点编辑、删除、撤销和恢复。
- 导线主体固定在创建时的柜面内，两端通过短引线连接真实端子；移动镜头或切换视角不改变已有线路，遮挡按场景深度处理，存档保留布线所在柜面。
- 背面布线平面取自 `DQG11` 安装板的实际网格和旋转，向外偏移 3 mm；不能使用 `DQG01` 整柜的世界包围盒代替背板，否则会因柜体旋转和底座突出而将导线放到柜外。
- 背面线槽内的导线根据原线槽盖网格局部抬入槽腔，距盖内侧 10 mm，避免被槽底遮住；槽内相邻折点之间的曲线不会向柜外鼓出。预览、成品、高亮及节点编辑共用该路径，旧存档自动适配，退出接线模式后盖板仍正常遮挡导线。
- KM5–KM7、FR3 背面导线保留真实连接点位置，以立体细管向外引出并绕过器件边缘（间距 10 mm），中段贴柜面。预览和成品共用路径，自动引出段不保存为用户折点。
- 背面跳线模式下，FR 的 2T1／4T2／6T3（FR.T1／T2／T3）与电机之间也使用立体软跳线，忽略旧柜面折点；普通电线仍使用上述柜面布线规则。
- 选中导线后左下角显示只读属性：原色块、颜色名称（自定义色为十六进制值）、起点及终点的器件名称与端子标注。普通提示不覆盖属性，错误提示仍可见；取消选择后恢复最新状态提示。
- 跳线模式下连接电机端子排 `DuanZiPai_7` 与电机端子，始终生成固定在真实端点的立体软跳线；下垂量为端点距离的 15%（上限 15 cm），切回电线模式仍显示。接线过程的空白点击和旧存档中的柜面折点不影响此类跳线路径；其他导线保持原折点规则。自动软线可选择、删除和撤销，但不能插入曲线采样点。
- 支持端子悬停提示：深灰提示框、白色端子名、黄色引线指向实际吸附中心。
- 支持端子排黄色分区备注，标明三相电源、指示灯、旋钮/按钮、PLC、中间继电器、变频器、接触器、FR 等端子区域。
- 排故视角在柜体原有 `DuanZiPai_5` 上提供 SB1–SB3 的 12 个连接点及“按钮（SB）端子区”备注，不生成重复模型。
- 排故背面按钮端子排左侧新增 14 位“电源端子区”：两组 U/V/W/N 和三组 24V+/24V-，与现有交流、直流电源共用供电；支持属性查看、接线、测量和接线存档。
- 柜体背面 SB1–SB3 与正面同名按钮共用触点状态，使用相同的 3 mm、0.1 秒按压回弹动画；点击可查看状态、常开/常闭触点和 `DuanZiPai_5.a1–a12` 连接点属性，仿真时按下操作、松手复位。
- 提供三相电源、断路器、按钮、旋钮、指示灯、接触器、热继电器、电机等离散电气行为。
- 提供万用表、验电笔/探针、示波器和转速表，测量数据来自同一仿真快照。
- 提供按用户附件顺序排列的六张原理图，支持手动循环翻页、独立收缩及大图查看。
- 保留自由接线、仿真、仪表排故和虚拟 PLC；旧任务、标准接线、自动验收和 A–D 本地考试已移除。
- 兼容原版 `.cc3d` 的 `element`、`customPoints`、`line`、`ropeLine` 四个根结构，并保留未知字段。
- 接线、截图和录屏帧序列均保存到本机；仅用户主动连接 PLC 时启动 S7 通信。
- 场景 PLC_1、PLC_2 支持独立属性、60 个端子关联、逐点 M/Q/DB 位映射和真实 S7-1200/S7-1500 双向联动；非仿真模式只读，断网后手动重连。PLC 配置随 `.cc3d` 保存，详见 [PLC 联调说明](Docs/PLC联调说明.md)。

## 原始素材接入

仓库内已有完整的 `Assets/OriginalContent/` 时，通过资源检查后即可打开项目，无需重新导入。只有需要从原素材重建资源时才执行以下步骤；它们不能替代 Git LFS 下载：

1. 将包含完整 `.meta` 文件的原 `Assets` 子集放到项目根目录 `OriginalAssetsSource/`。
2. 在 Unity 菜单执行 `Electrical Sim > Import Original Assets`。
3. 导入器将资源整理到 `Assets/OriginalContent/`，并创建或更新 `OriginalVisualRegistry.asset`。
4. 自动识别失败的 Prefab 可在注册表中按 `DeviceId` 或 `TypeId` 指定。

不要删除原资源的 `.meta` 文件；Prefab、材质、贴图和端口 Transform 依赖原 GUID 关系。

## 下载与恢复

### 方式一：完整恢复包

使用维护者提供的 `tlfdj-unity-complete-*.zip`，解压到新目录，保留全部 `.meta` 文件。完整包包括源码、真实资源、依赖声明和项目设置，不包括旧 `Library` 缓存。

在解压后同时包含 `Assets`、`Packages`、`ProjectSettings` 的目录中打开 PowerShell，执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Test-ProjectResources.ps1 -ReportPath .\Build\Reports\resource-integrity.json
```

看到 `PASS` 后，按下方[Unity 编辑器](#unity-编辑器)步骤打开项目。若包内包含 `RESTORE-MANIFEST.json`，检查工具还会核对清单中文件的大小和 SHA-256；开始开发后修改文件会导致相应哈希检查失败，这是预期行为。重新打包修改后的项目时，先将旧清单另存到项目目录之外。

### 方式二：GitHub Download ZIP

模型、贴图、字体、资源注册表和部分 Prefab 使用 Git LFS。仓库管理员需要在 **Settings → General → Archives** 中启用 **Include Git LFS objects in archives**，再重新下载 ZIP。旧 ZIP 不会自动补齐资源。[GitHub 官方说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/managing-git-lfs-objects-in-archives-of-your-repository)

解压后运行与方式一相同的检查命令。若下载的是不含检查工具的旧版本，可先检查以下关键资源：

| 文件 | 正常内容 |
| --- | --- |
| `Assets/OriginalContent/OriginalVisualRegistry.asset` | Unity YAML 资源注册表，包含原始模型引用 |
| `Assets/OriginalContent/GeneratedVisuals/OriginalLabEnvironment.prefab` | 完整实训室 Prefab；本次验收版本约 36.6 MB |

如果文件只有以 `version https://git-lfs.github.com/spec/v1` 开头的几行文字，说明仍是 LFS 指针。文件名存在不代表真实内容已下载；删除 `Library`、调整画质或重新导入都无法补回这些资源。

### 方式三：Git 与 Git LFS 克隆

安装 Git 和 Git LFS 后，在用于存放项目的目录执行：

```powershell
git lfs install
git clone https://github.com/ckw1580-boop/tlfdj.git tlfdj-complete
cd tlfdj-complete
git lfs pull
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Test-ProjectResources.ps1
```

普通 ZIP 解压目录没有 `.git`，不能直接在那里执行 `git lfs pull`。若服务器提示对象不存在或配额问题，需要维护者补传资源或处理 LFS 服务问题，详见[项目恢复说明](Docs/project-recovery.md)。

### 缺失资源时的处理

编辑器打开后会自动检查实际文件和原始资源注册表；点击 Play 前还会检查当前场景的注册表引用。缺失时提示恢复方法并取消运行，自定义构建菜单和标准 Unity 构建也会进行检查。完整问题列表写入 `Build/Reports/resource-integrity.txt`。

可通过 **Electrical Sim > Validate Project Resources** 手动复查。运行时如果注册表、环境或已登记的设备 Prefab 缺失，会立即报错，不再默默启动方块、圆柱组成的替代场景。重新执行 **Electrical Sim > Install Training Scene** 时会自动绑定现有原始资源注册表。

## 启动与构建

### Unity 编辑器

1. 完成资源检查后，用 Unity Hub 添加本项目目录。
2. 使用 Unity 2022.3.62f3c1 打开项目。
3. 打开 `Assets/Scenes/ElectricalTraining.unity`。
4. 点击 Play，程序直接进入实训场景。

首次打开保持联网，让 Package Manager 下载依赖并完成资源导入。完整恢复包不包含依赖缓存，因此不保证全新电脑可以离线完成首次安装；构建后的默认离线运行不受影响。

### Windows x64

在 Unity 菜单执行：

```text
Electrical Sim > Build Windows x64
```

默认输出为：

```text
Build/Windows/ElectricalTraining.exe
```

构建产物可断网启动；不需要原始 EXE、原 `App.dll` 或真实 PLC 服务。

### 生成完整恢复包

先在 Unity 中执行 **Electrical Sim > Validate Project Resources**，通过后在项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Build-CompleteProject.ps1
```

默认输出为 `Build/Recovery/tlfdj-unity-complete-时间戳.zip` 及对应的 `.sha256` 文件。工具从本地实际文件打包，先检查资源和 `.meta`，再逐个读取压缩内容并验证 SHA-256；不完整的输入会阻止打包，失败过程可能留下 `.partial` 文件，不能作为恢复包使用。

发布前应将 ZIP 解压到新目录，完成资源检查及 Unity 场景运行验收，再作为 Release 附件交付。修改源码、资源或 README 后，需要重新运行打包工具，已有 ZIP 不会自动更新。

## 操作说明

### 模式

| 快捷键 | 模式 | 说明 |
| --- | --- | --- |
| `1` | 视角 | 浏览场景和切换预设视角 |
| `2` | 拖动 | 选择并拖动允许移动的器件 |
| `3` | 接线 | 连接端子、编辑和删除线路 |
| `4` | 仿真 | 操作按钮、断路器和保护器并观察电路状态 |
| `5` | 排故 | 保持当前视角，使用故障和测量工具 |
| `Esc` | 视角 | 返回视角模式 |

### 相机

- `W/A/S/D`：平移。
- `Q/E`：下降/上升。
- 按住鼠标右键：旋转视角。
- 鼠标滚轮：缩放。
- 工具栏“接线视角”：机柜、端子和器件的全景布局。
- 工具栏“排故视角”：机柜居中、接近原软件构图的正面近景。

### 接线

- 在接线模式中先点击起始端子；电线会随鼠标实时预览。
- 左键点击空白位置可连续添加路径点，再点击另一个端子完成连接；生成后的电线会平滑经过这些路径点。
- 再次点击起始端子可取消当前接线。
- 左键点击 KA1–KA6 中间继电器、正面 KM1–KM4 或背部 KM5–KM7 交流接触器、FR1–FR3 热继电器本体，在共用的左侧 280×240 浮窗查看白底黑色符号原理图；点击不同器件切换标题和图纸，保留接线起点和路径点。窗口外可继续接线，点击“关闭”或离开接线模式收起图纸。
- 六张原理图的图册位于左侧器件原理图与底部模式/属性框之间，随窗口高度适配，并与上下两个框保持间距。点击右侧“◀”可滑入屏幕左侧，点击左缘“▶”展开；与底部模式框独立收缩，顶部首页和“原理图”按钮同步控制此框。
- 单击已有导线可选中并显示黄色高亮和路径节点；拖动节点可在柜面上调整导线路径。
- 双击导线线段可在点击位置新增路径节点。
- `Delete` 删除当前选中或最近一条线路。
- 已选中路径节点时，`Delete` 优先删除该节点，再次按下才会删除整条导线。
- `Ctrl+Z` / `Ctrl+Y` 撤销或恢复。
- 导线和接线预览固定在电气柜表面：接线视角使用正面布线层，排故视角使用背面布线层，两个平面都不会随相机移动或旋转改变位置。
- 上端子排保持原始上侧物理锚点，下端子排使用下侧锚点；切换线型或视角时两者都不会翻转到另一侧。
- 鼠标停留在端子上会显示配置中的语义名称，例如 `SB8_COM2`、`KA6_8`、`KM1_53NO`。
- 提示 UI 不阻挡端子点击、测量和接线射线。

### 混合罐、场景泵与液位传感器

`DuanZiPai_8` 的18个端子保留内部标识及原锚点，显示前缀 A/B/C/D 分别改为下限位、中限位、上限位、上上限位，Diancifa1/2/3 改为电磁阀1/2/3。传感器按安装位12、11、10、9从低到高绑定；电磁阀按安装位1、2、3绑定。

验证控灯：`24V+ → KA1_13`，`KA1_14 → 24V-`，`24V+ → KA1_9`，`KA1_5 → HL1_L`，`HL1_N → 24V-`。开启总供电后 KA1 吸合、HL1 点亮；断开线圈供电后释放、灯灭。将 KA1_13 改接已供电 PLC 的 Q 输出即可由 PLC 控制。继电器规格来自 `IntermediateRelayDefinition`，运行状态由接线重建，不另存吸合状态。

### 转速表与变频测速

点击“排故”进入模式后，电机前端绿色轴头测点立即显示，无需先选择仪表或将鼠标悬停在测点上。选择“转速表”后，橙色三维表体跟随鼠标，将探头移到轴头，测点变亮后点击吸附，表内屏幕和仪表区同步显示该电机的实际转速。点击表体可拿起并换测其他电机；切换仪表会收回表体并保留绿色测点，退出排故或重置训练会一并隐藏测点。未接触显示 `—`，静止显示 `0 rpm`，反转显示转速绝对值。电机顶部六个接线柱不作为测速点。

G120 输入 `L1/L2/L3` 需要三相供电，输出 `U2/V2/W2` 经端子排、导线和闭合接触器接到电机 `U1/V1/W1` 后，电机按变频器实际输出转速运行。面板的 `P1120/P1121` 决定加减速过程；交换任意两根输出相线会改变方向。输出缺相、断电或变频器故障后电机滑行停转，默认 3 秒；现有制动状态默认 1 秒停转。输出短接、接地或与工频电源混接会停止有效驱动并提示故障。工频额定转速仍为 1450 rpm；本次未增加负载转矩及双速绕组模型。

三维表体复用原 `Tachymeter` 网格和贴图，可通过 Unity 菜单 `Electrical Sim > Build Tachometer Model` 重建预制体。截图与测试结果位于 `Build/Reports/tachometer-*`。

离散电气图以端口和导电关系为基础，每帧迭代到稳定状态，包含：

- 三相电源和相序；
- 断路器、熔断器；
- 常开/常闭按钮与触点；
- 接触器线圈、主触点、辅助触点、自锁和互锁；
- 热继电器和过载状态；
- 电机正转、反转、停止与制动；
- 短路、断路和非法反转检查。

## 仪表与排故

点击“排故”或选择工具时保持当前相机位置和朝向；仅点击视角菜单中的“排故视角”才切换到排故近景。

### 三维万用表

点击“排故”→“万用表”，橙色表体出现在当前视野右下方，默认使用交流电压档。表内液晶屏与独立右侧仪表区同步显示档位、读数和红黑测点名称。选中万用表后，可用测量端子不受之前选择的电线或跳线工具影响。

1. 点击红笔、黑笔或表体对应的红色测量插孔、黑色 COM 插孔，拿起相应表笔，再点击可见端子吸附；导线两端通过各自所接端子测量。
2. 再次点击已连接的表笔可单独换测。两笔可以接同一端子，笔柄向两侧倾斜，笔尖保持在真实接点。切换视角后，已接表笔仍固定在点击时的物理锚点，不会跳到柜体另一面的同名端子。
3. 点击旋钮循环切档，或直接点击对应档位标记。按住表体外壳并拖动，可沿开始拖动时的相机平面移动；松手后保持世界位置，不随相机移动。连接软线随表体和表笔更新。
4. 表体“收笔”或右侧“收回表笔”清除两笔连接；表体“归位”或右侧“仪表归位”将表体移回初始位置，保留已接测点。切换仪表、退出排故或重置训练会清除连接、隐藏万用表并停止蜂鸣。

| 档位 | 读数与行为 |
| --- | --- |
| OFF | 关闭测量及蜂鸣，显示 `OFF` |
| 交流 V~ | 相线与零线为 `220.0 V`，不同相线之间为 `380.0 V` |
| 直流 V DC | 正常直流供电为 `24.0 V`，红黑笔对调为 `-24.0 V`；数值始终为红笔电势减黑笔电势 |
| 蜂鸣通断 | 按当前导线、端子排内部连接及闭合触点判断；导通显示“导通”并蜂鸣，断开显示 `OL` 和“断开” |

通断档任一测点连接启用的电源输出时，显示“请先断电”，不蜂鸣；两点同电位也执行此规则，与电源隔离的支路仍可测量。没有拿起表笔或拖动表体时，可在排故模式操作现有供电开关、断路器和按钮，保留已接表笔以便断电后复测。测量遵守 UI、原理图大图窗口及场景实体的遮挡规则。

未接齐表笔显示 `—`；两点均失电时电压为零；单端悬空或跨交流/直流电源参考不明确时提示“参考不明确”；电势冲突显示 `Err`。变频器输出及其连接网络的电压测量暂不支持，运行中的变频输出仍触发通断档带电提示。当前采用理想电路模型，不提供电流档、电阻档、线圈或电机绕组电阻、变频波形及软线物理仿真。

表笔和连接软线不会改变被测电路，也不加入导线、撤销历史或 `.cc3d` 存档；仪表位置、档位和测点连接均不保存。模型及材质可通过 Unity 菜单 `Electrical Sim > Build Multimeter Model` 重建，预制体位于 `Assets/ElectricalSim/Resources/Multimeter.prefab`。

## 虚拟 PLC

- PLC/IO 由 `LocalPlcRuntime` 在本地模拟扫描周期和内部触点。
- 默认不连接外部设备；用户主动连接真实 PLC 时，通过 S7 通信进行联动。不依赖 `GXTcp` 或 `NetToPLCsim`，不支持 Modbus。

## `.cc3d` 兼容

读写器保留以下四个根结构：

```text
element

line
```

设备 GUID、类型、端口、折点、颜色、线径及无法识别的扩展字段会在读取和保存过程中保留。旧存档缺少新增物理锚点字段时会按兼容规则恢复。

## 本地数据

接线通过顶部“保存接线”保存为 `.cc3d` 文件。每次保存均可选择目录和文件名，覆盖已有文件时由文件窗口确认。文件夹按钮用于“打开接线”；打开后进入接线模式，可继续编辑节点、删除和新增导线。

当前接线有未保存修改时，打开前可选择“保存后打开”“放弃修改并打开”或“取消”。取消保存或保存失败会中止打开；文件损坏、缺失路径点、重复导线 ID 或端子不匹配不会清空当前接线。撤销回已保存状态后不再提示未保存修改。

接线默认目录是 `Application.persistentDataPath/Projects`，Windows 构建中通常为：

```text
%USERPROFILE%/AppData/LocalLow/同立方/电气控制系统仿真软件/Projects/
```

本次运行会记住最近成功使用的目录和文件名。存档仅包含已完成的导线及其路径、样式和柜面归属；未完成接线预览、相机视角、设备位置和运行状态不通过此功能恢复。空接线也可保存。

截图和录像默认位置：

```text
文档/电气控制系统仿真软件/
```

该目录用于保存截图和录屏帧序列。移除考试功能不会删除用户已有的本地文件。接线的保存与打开使用系统本地文件选择窗口，无需网络。

## Git 与大文件

模型、贴图、音视频和构建资源可能超过普通 Git 文件的合理大小。提交前请确认 Git LFS 已安装并检查 GitHub 单文件 100 MB 限制：

```powershell
git lfs install
git lfs fsck --objects
git lfs status
git status
```

从拥有真实资源的原仓库补传当前主分支及其历史引用的 LFS 对象时，执行：

```powershell
git lfs push --all origin main
```

`.gitattributes` 将 `ProjectSettings/` 保留为普通文本，避免项目配置因 LFS 指针而无法读取；规则在后续提交中生效，不会改写旧提交。`git lfs fsck --objects` 用于检查实际对象；旧历史中部分文件与当时的 LFS 跟踪规则不一致时，完整 `git lfs fsck` 的指针规则报错需与对象缺失分开处理。

是否提交或推送由当前维护者决定；开发和测试过程不会自动执行 Git 提交或推送。

## 离线边界

自由接线、仿真、原理图查看和接线保存无需 PLC 或服务器。真实 S7-1200/S7-1500 联动是用户主动开启的可选功能，需要与 PLC 的网络连接，详见[PLC 联调说明](Docs/PLC联调说明.md)。首次安装 Unity 依赖也可能需要联网。

以下功能明确不实现：

- 账号登录和身份验证；
- 联网更新和热更新；
- 云端考试、云端成绩和竞赛平台接口；
- Modbus 及 S7-1200/S7-1500 联动范围之外的现场总线集成；
- 依赖原 EXE 或原 `App.dll` 才能运行的逻辑。

原资源确实缺失或损坏时应记录为阻塞项，不使用近似素材冒充像素级复刻结果。
